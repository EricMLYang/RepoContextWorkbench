## 2. 驗證方式與邊界

**自動測試**：`python3 -m pytest -q` → 146 passed, 1 skipped（略過的是需要登入 claude CLI 的 agent 測試）。

**瀏覽器走查**：Chrome 視窗 1280×860、暫存 spine、5 個假 git repo（含一個超長名稱）、2 組（共通／知識寫作）、`scripts/screenshot.py` 的 seed_demo 事件＋知識寫作組事件＋未分類 timer 事件＋8 筆回填的舊決策。走查項目：

1. 首屏載入、console 無錯誤（含重新整理後）
2. 切到「知識寫作」：卡片、計數、頁尾範圍一致；共通組內容消失；全域警示仍可見並標示
3. 「＋」開對話框：焦點在搜尋框、checkbox 有名稱、已選數正確；Esc 關閉、焦點回到「＋」、scope 未改
4. Repo／活動／關係三個分頁：欄位、排序箭頭、依時間排序、跨組關係保留另一端
5. 碰撞台：空送出有錯誤訊息；草稿重整後仍在、範圍也記得
6. 詳情對話框：主鈕標示、五個動作、可複製；「所有組標為已讀…」確認框顯示則數
7. 關掉伺服器再更新：紅點＋橫幅、保留上次資料、靜默行清空

**未做且不宣稱**：
- 中文輸入法選字時按 Enter 的實際行為（只有程式檢查）
- Windows／VDI 上 pywebview 原生視窗、螢幕閱讀器
- 真 Agent 會話與 terminal 生命週期、「記錄結果」從 UI 端到端（只有單元測試）
- 完整 WCAG 稽核（只有局部對比估算）
- 檢討 §5 第三輪（搜尋與篩選進階、表格欄位選擇、會話結果回寫入口的日常使用）
- 檢討 §5 的人工驗收任務（兩組、十筆以上事件、找到最需要處理的一件並執行）——這是 L4，要 Eric 真用
