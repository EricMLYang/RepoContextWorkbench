## 1. 裁定與理由

| 舊裁定（v2） | 新裁定（本檔） | 理由 |
|---|---|---|
| §7「不內嵌 terminal」——P16 開**原生**終端視窗 | **內嵌 terminal 是工作台的一級公民**：xterm.js＋PTY，agent 會話開在工作台底板 | 使用者的實際工作形態是「看狀態→直接跟 agent 講」，切出去開原生視窗打斷心流；P16 的「帶料」邏輯不變，只是料開在自家面板 |
| §9-8 S4 形態留給實作（tkinter？pywebview？） | **pywebview 定案**（桌面視窗；瀏覽器模式降為過渡替代） | 2026-09-01 裁定 ①；同一份 HTML 前端、OS 內建 webview、零 Electron/Tauri 工具鏈 |
| S4＝監控台（只讀＋少量行動出口） | S4＝**工作台**（監控＋操作＋對話三合一） | 「太像玩具」的根因：只能看不能做。監控四判準仍管**事件流與通知**；操作面板與 terminal 不受「無事不報」管（操作面板裁定已在 UI 第二輪成立） |

**不變的骨架**（v2 鐵律照舊）：引擎/私有分離、兩份純文字資產、殼只 poll 脊椎、本地優先、教練規格出手留痕、agent 無關性。terminal 只是殼的一塊面板，**不含邏輯**——它跑的是引擎 CLI 與 agent CLI 本人。

## 2. 版面（IDE 三件套＋狀態列）

```
┌─────────────────────────────────────────────────────────────────┐
│ topbar  ⚙ repo 工作台｜碰撞台輸入框（fire-and-forget）｜範圍｜   │
│         未讀 badge｜全部已讀｜重新採集                            │
├──────────────┬──────────────────────────────────────────────────┤
│ sidebar      │ main（分頁）                                      │
│ 組切換        │  事件流：需要你判斷的（問句＋出口）→ 未讀事件      │
│ repo 勾選＋   │          （interrupt 紅頂）→ 未結 open loops      │
│  狀態微標＋   │  簡報：產生早晨簡報（落 presented）＋內容檢視      │
│  ▶每repo會話  │  深看：全量狀態表＋量測                           │
│ 勾選存成組    │                                                  │
│ audit 紅字   │                                                  │
├──────────────┴──────────────────────────────────────────────────┤
│ terminal 面板（可拖高度；Ctrl+` 收合）                            │
│ [shell ✕][agent:g1 ✕] … ＋shell ＋agent 會話（帶料）             │
│ xterm.js（真 PTY；agent 會話＝claude 帶打包料＋MCP 掛載）         │
├─────────────────────────────────────────────────────────────────┤
│ statusbar  碰撞N｜outcome 回連｜命中率｜生出 repo｜存活率｜採集於  │
└─────────────────────────────────────────────────────────────────┘
```

**體驗要點**：
- 碰撞台常駐 topbar——任何時刻 Enter 丟想法，判定走未讀回程（維持 fire-and-forget）。
- sidebar 勾選＝P2 臨時組合，同步縮放「需要你判斷的」「碰撞範圍」「＋agent 會話的帶料範圍」。
- 每個 repo 列有 ▶：在該 repo cwd 開 agent 會話（P16，`--mcp-config` 指回 spine）。
- interrupt（system-unsure）事件紅色置頂＋瀏覽器通知 best-effort；其餘累積進未讀。
- terminal 會話生命週期**獨立於視窗連線**：關工作台再開，會話還在（replay 最後 ~200KB）。

## 3. 架構

```
pywebview 視窗（或瀏覽器過渡模式）
   │  http://127.0.0.1:<隨機埠>/?token=<啟動隨機token>
   ▼
stdlib ThreadingHTTPServer（webui.py；零框架依賴）
   ├─ GET  /            工作台頁（xterm.js 由 /static 本地供應，離線可用）
   ├─ GET  /api/state   輕量輪詢：脊椎未讀（interrupt 分類）＋loops＋stats＋終端清冊
   ├─ GET  /api/scan    P3 採集（開頁/切組/勾選/手動才跑）
   ├─ POST /api/*       collide/ignore/close_loop/save_group/brief/ack
   ├─ POST /api/term_create│term_kill      會話管理
   └─ GET  /ws/term/<sid>  WebSocket（手寫 RFC6455 最小子集，零依賴）
          ▲ binary frame＝PTY 原始輸出（不解碼，escape/半個UTF-8都不折斷）
          ▼ text frame＝JSON {t:"i",d}輸入／{t:"r",c,r}resize
term.py TermManager
   ├─ shell 會話：$SHELL（Windows：COMSPEC）
   └─ agent 會話：session.build（P6 打包＋.mcp.json 掛載）→ claude <帶料prompt>
      POSIX＝stdlib pty；Windows＝pywinpty（缺套件給人話錯誤，VDI 移植時實測）
```

**安全**（檢討④ VDI multi-session：localhost 埠跨 session 共享）：只綁 127.0.0.1＋每次啟動隨機 token，URL 帶 token 才服務（含 WS；/static 例外）。pywebview 視窗拿完整 URL，其他本機使用者猜不到。正式版若上多人 VDI 再評 named pipe。

**依賴盤點**：執行期新增 pywebview（optional）＋前端 vendor xterm.js 5.5.0／addon-fit 0.10.0（MIT，`repo_context/static/`，離線可用）。引擎核心依舊只有 PyYAML。

**互動樣貌**（補 v2 §4.5 文字樣貌沒寫到的那一層——每個〔〕對應哪個原語、按下後脊椎落什麼、卡變什麼）：

| 卡 | 出口 | 引擎原語 | 脊椎留痕 | 卡的變化 |
|---|---|---|---|---|
| 需要你判斷（inactive） | 降 tier | `registry.set_field` | `decision [monitor] repo:X` | 消失（下次採集不再問） |
| 需要你判斷（任一） | 本週排進度／標記本週不動 | — | `chosen [monitor] repo:X` body `snooze:<qkind> until:<date>` | 消失，7 天內不再浮出 |
| 需要你判斷（dirty） | 開 agent 收尾 | P16 `term_create`（origin＝卡 key，task＝收尾指令） | agentmark | 卡留著；會話出現在 sidebar |
| 碰撞回程 | 照建議落／改落點…／升格 incubator | P8 `route` | `decision [route]`＋`chosen ref:collision:<cid>` | 消失 |
| 碰撞回程 | 深撞：開會話 | P16（origin＝collision:<cid>，帶想法＋判定） | agentmark | 卡留著；會話帶「碰撞 <cid>」來源 |
| 碰撞回程／其他未讀 | 丟棄並記錄／忽略並記錄 | — | `chosen ref:…` body 忽略並記錄 | 消失 |
| 准打斷 | 重跑判定 | P7 `spawn_detached` | 新判定事件 | 回程到了原地換卡 |
| 處理中 | （無） | — | — | 回程到了原地換成碰撞回程卡 |
| 未結 loop | 開碰撞／延 7 天／關閉 | — ／同 # 新 due 再 opened／closed | `open-loop [monitor]` | 預填輸入框／due 更新／消失 |

**規則**：自己出手的留痕（presented／chosen／monitor·route·spawn 的 decision）不進收件匣；
被 `chosen ref:` 到的事件＝已處理，**不用等「全部已讀」就消失**；「全部已讀」只是 last_seen 位移，不落 chosen。
