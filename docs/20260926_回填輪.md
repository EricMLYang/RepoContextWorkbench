# 回填輪（2026-09-26）

> **性質**：落地記錄。程式已落地、測試全綠（247 tests）；真資料已跑完抽取與彙整，候選**尚未收進 spine**（等使用者審）。

## 1. 為什麼

反芻輪接上正式 spine 後第一輪推薦 0 筆——spine 沒有判斷、沒有未結、沒有交接，「手上工作」是空的；
agent 開場也接不上。但使用者與 agent 過去的會話都在 `~/.claude/projects/*/<session>.jsonl`（約 120 場、470MB），
判斷與沒做完的事都在裡面。回填＝把冷啟動的材料從既有紀錄撈回來，而不是等它慢慢長。

## 2. 落地（`repo_context/backfill.py`、`ctx backfill`）

| 段 | 做法 |
|---|---|
| scan | 會話紀錄裡最常出現的 cwd → 已登記 repo（最長路徑前綴；Drive 舊路徑依資料夾名）。30 分鐘內有更新＝還在寫，不碰；對不到的列出來 |
| compact | 只留使用者原話（標 `[tN]` 輪次）、agent 文字、工具一行；tool_result／thinking／系統標記全丟。470MB → 79 萬字 |
| extract | 每 4 萬字一段，一段一次 `claude -p --model sonnet`（在 spine 目錄、唯讀工具）→ 判斷／待辦／完成／下一步／目標線索（JSON；解析失敗重試一次） |
| consolidate | 同 repo 所有會話依時間彙整：後來推翻的判斷只留最新、後來做完的待辦剔掉、看不出的標 uncertain |
| review／accept | 候選不自動寫入；`accept X d1 t2 h` 才寫，source `backfill`、內文註明「回填自 日期 會話 sid」；交接最後寫（＝上次做到哪）；不重收 |

紀律：
- 目標只列線索（goal_hints），不代寫進 registry——目標只有使用者能給。
- 可中斷續跑：`.state/backfill/sessions/<sid>.json` 在就不重抽；單場失敗記下繼續，最後 exit 1 浮出。
- 歸屬會變：後來登記了更精確的子專案，已抽過的會話改掛過去、兩邊重彙整、沒會話的舊候選清掉（不重抽）。
- `claude -p` 在 spine 目錄跑：hooks 靜默；它自己產生的會話紀錄落在 spine 的 project 資料夾，對不到 repo，不會被回填回來。
