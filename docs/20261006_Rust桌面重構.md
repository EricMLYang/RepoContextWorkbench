# 2026-10-06 Rust 桌面重構

> 在 `rust-desktop` 分支，一天內把 `repo_context`（Python）整份搬成 **Rust 引擎＋Tauri 殼＋React 前端**。
> 搬遷規約、合約與每一條刻意差異在 `RUST_PORTING.md`；IPC 合約在 `../desktop/IPC.md`。本檔記「做了什麼、驗了什麼、還沒驗什麼」。

## 動機

- **一支執行檔**：CLI、MCP server、Claude Code hooks 共用 `ctx` 一支 binary，不再依賴使用者機器上的 Python 版本、venv、`pip install -e`。
- **桌面殼要輕**：pywebview＋手寫 HTTP／WebSocket 的工作台換成 Tauri v2（系統 WebView、不用 Electron），IPC 取代本機 HTTP——
  不再開 127.0.0.1 埠、不需要 URL token；閒置不輪詢（檔案監看用 OS 事件）。
- **會話（PTY）生命週期獨立於視窗**：Rust 端 `portable-pty` 管 PTY，關視窗只是隱藏，agent 照跑。
- **前端可維護**：原本單檔 `workbench.js` 換成 React＋TS 元件（牌／收件匣／會話／深看），業務判斷移回引擎。

## 架構

```
crates/ctx-core/   引擎 lib（不依賴 Tauri／clap）：一個 Python 模組對一個 .rs；workbench/{state,actions}.rs 給桌面用
crates/ctx-cli/    bin `ctx`：clap CLI＋MCP（stdio JSON-RPC）＋hooks；lib＋bin 讓 MCP 單元測試在行程內跑
desktop/src-tauri/ Tauri v2 殼：IPC 命令、PTY Channel 轉接、notify 檔案監看、選單列未讀數、通知、單一實例、PATH 補齊
desktop/src/       React（Vite＋TS）：只畫畫面；偵測 __TAURI_INTERNALS__ 走 IPC，否則走 Python 版 HTTP（對照用）
```

合約不動：spine 事件 md、`registry.yaml`／`config.yaml`（保留未知鍵）、`.state/`、CLI 旗標／`--json`／exit code、MCP 工具與錯誤形狀。
搬遷期間兩版讀寫同一個 spine 是常態。

## 怎麼分工（各波）

主 agent 定規約（`RUST_PORTING.md`）與 workspace 骨架，之後每波開多個 agent 各在 worktree 搬一批互不依賴的模組，完成後 merge：

| 波 | 內容 |
|---|---|
| 0 | workspace 骨架、搬遷規約、`testkit`（temp spine、假 git repo，照 `tests/conftest.py`） |
| 1 | 葉節點：pack／collect／agentmark／agents／knowledge |
| 1′ | 基礎層：config／locking／spine／registry／ops／route／notify／spawn；並行：前端搬 React |
| 2 | brief／summary／digest／upstream／collide／agentsetup；crossref／ruminate／context／repocard／session；Tauri 殼＋Rust PTY；status |
| 3 | agentapi／hooks／timer／backfill；webui state／actions → `ctx_core::workbench`，Tauri 殼全接上 |
| 4 | ctx-cli：全部子命令＋MCP server＋對拍腳本 |
| 收尾 | 清重複（見下）、GUI 終端機實測、文件 |

平行搬留下的重複在收尾時合併：`fsutil`（路徑／檔案）與 `pystr`（字串的 Python 語義）分工、`exe.rs` 統一「找 ctx」與 detached spawn、
`pyjson` 移進 ctx-core（取代 `agentmark::py_dumps`）、五份 JSON 真值判斷合成 `pystr::truthy`、`Repo → RepoSpec／RepoRef` 一律走 `From`、
`Event::stamp()`。行為不變，以測試與對拍為證。

## 對拍方法與結果

- `scripts/parity.sh`：用 Python CLI 建 fixture（3 個假 git repo、兩組、關係、export、決策／todo／handoff／碰撞、回填候選、一場會話），
  複製兩份各跑 Python 與 Rust 的同一組指令，比 exit code、stdout（JSON 解析後比；人話逐字、路徑與時間戳正規化）、
  每步之後整個 spine 目錄（事件檔、dead-letter、registry 解析後比、`.state` JSON 解析後比），以及 MCP 工作層／管理層各一串 JSON-RPC。
  **結果：153 項（CLI 151＋MCP 2）全過**；允許差異只有 `.agent_logs/`（provider 除錯 log）與 `.mcp.json`（指令改指 Rust ctx）。
- `scripts/parity_state.py`：工作台 `get_state`／`get_scan`（全部、單組、臨時組合）兩版 JSON 對拍——**全部相同**。

## GUI 終端機端到端實測（release .app）

temp spine（`ctx init`＋`registry add` 兩個假 git repo＋`group add demo`），`npx tauri build --bundles app`，
`open -n "Repo Context.app" --args --spine <dir>`。截圖在 `assets/20261006_tauri/`。

| 步驟 | 結果 |
|---|---|
| 啟動、讀 `--spine`、畫出工作台 | ✅ `terminal_0_launch.png` |
| 點「＋ Shell」開會話 | ✅ 側欄多一個「shell · spine」、終端面板出現 zsh 提示字元（`terminal_1_shell_open.png`） |
| 在終端面板輸入 `echo hello-$((40+2))`＋Enter | ✅ 輸出 `hello-42`（`terminal_2_reopen_release.png`；鍵盤 → xterm → `term_write` → PTY → Channel → xterm 全程） |
| 關視窗（紅色關閉鈕） | ✅ 視窗隱藏、程序與 zsh 子程序都還在 |
| `open` 再開一次 | ✅ 單一實例把既有視窗叫回來，會話還在、剛才的輸出都在 |
| replay | ⚠️ 視窗是隱藏不是銷毀，叫回來時 xterm 仍是同一個，**沒有走到 replay**；GUI 裡 replay 只在「重新連線」時用到。replay 的順序由 `crates/ctx-core/tests/term.rs`（`attach_replay_then_live_in_order` 等）驗 |

實測過程的教訓：用 System Events 打全域鍵盤／點螢幕座標時，使用者若同時在用電腦，焦點會被搶走、字打進別的 App。
之後要自動化 GUI，應在專用使用者或無人使用時跑；只截特定視窗用 `screencapture -l <CGWindowID>`（不受遮蔽影響）。

## 未做與已知風險

- **Windows／VDI 完全未測**：PTY（ConPTY）、`agentmark.pid_alive`（Windows 暫時一律回 true）、`ctx app`（只找 macOS .app）、路徑與 detached spawn。
- **tray、通知、hotkey 未手動操作驗證**：選單列未讀數、「開啟工作台」／「結束」、會話結束通知、開機自啟、視窗內 Ctrl+` 收合終端都只有程式碼與單元測試，沒有實機點過；全域 hotkey 尚未實作。
- **真 agent 會話未測**：只測了本機 shell 會話；`term_create` agent 分支（帶料開 claude、`.mcp.json`、agent 階段回報）沒在 App 裡跑過真 claude。
  `backfill run`、`collide --provider claude` 等呼叫真 claude 的路徑也只走 mock。
- ~~**`.app` 不含 `ctx`**~~（2026-10-07 已解）：`npm run bundle` 先編 Rust ctx、以 Tauri `externalBin` 放進 `Contents/MacOS/ctx`，
  App 照「自己 → 同目錄 → PATH」找到的是自帶那支，不會落到 PATH 上的 Python 版。`.app` 因此 10.4 → 15.6 MiB。
- **`ctx setup --claude` 不會自動替換 Python 版的 MCP 註冊與 hooks**：MCP 已註冊就略過；Python 的 `repo_context hook` 也被認成已掛。
  切換時要先手動移除（見下）。
- **未簽章、未公證**：.app 在別台 Mac 開會被 Gatekeeper 擋，需要右鍵開啟或 `xattr -d com.apple.quarantine`。
- 跨午夜跑對拍可能因日期不同失敗，重跑即可。

## 切換前要做的事（合併回 main 前）

1. `cargo install --path crates/ctx-cli`；`which -a ctx` 確認 Rust 版在 PATH 最前（或 `pip uninstall repo-context-workbench`）。
2. 停掉 Python 版的 `ctx timer`／`ctx app` 與進行中的 agent 會話；spine 先 commit。
3. `claude mcp remove repo-context -s user`；從 `~/.claude/settings.json` 刪掉含 `repo_context hook` 的 SessionStart／SessionEnd 兩筆。
4. spine 的 `.mcp.json` 若指向 `python -m repo_context` 就刪掉（`ctx session` 會重寫）。
5. `ctx setup --spine <spine> --claude --dry-run` 看過，再正式跑；`claude mcp get repo-context` 確認指向 `ctx mcp`。
6. 真用一輪（開工 context_for → 記判斷 → handoff、工作台開 agent 會話）沒問題，再合併 main、刪 Python 版。
