## 2. 對標掃描

- 查詢見 `benchmarks.md` R29 段。結論：
  - 「多選檔案丟給 agent」市面做法是 Aider 的「＋」與 Qoder 的拖進對話；Claude Code 本身要逐一 @。→ F-59。
  - ⌘K 主流是 cmdk（WAI-ARIA combobox）；不加依賴，自己寫，排名放引擎。→ F-58。
  - Claude Code `--settings <file-or-json>` 可以只對 App 開的會話加 hook（本機 `claude --help` 與 `-p` 實測）。→ F-60。
  - Backstage 類服務目錄都是「名片＋擁有者＋關係」——跟 F-57 同方向，維持輕量（存 spine、不寫進 repo）。

## 4. 非功能（這輪做完的）

- N-30 平行採集、N-31 原子寫入統一（§8 規則）、N-32 `git status --no-optional-locks`、唯讀 action 不再觸發整份 state 重抓（展開資料夾、開檔、讀筆記原本都會）。
- GUI 實測（N-21 部分）：用 `tauri build --no-bundle` 執行檔＋`--spine <副本>`（副本先拿掉 remote），截圖只拍該 pid 視窗、按鍵只送該 pid。
  鍵盤流程都過；抓到並修掉 3 個體驗問題（牌組被擠到最後、macOS 行內輸入建議蓋住結果、檔名中段命中排太前）。
  **滑鼠事件送 pid 不生效**（視窗不是 key window），點擊類流程（寫名片、⌘＋點挑檔、拖檔、差異切換）仍要使用者實測。
