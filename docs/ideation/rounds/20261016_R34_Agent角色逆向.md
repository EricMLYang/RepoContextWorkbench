## 1. 兩個產品裡 agent 的角色，一句話

| | BAT | Orca |
|---|---|---|
| agent 是什麼 | **產品本體**：內建聊天面板，agent 的每個訊息、工具呼叫、思考、用量都由 App 自己渲染 | **終端裡的一個程序**：終端是事實來源，App 只在旁邊讀狀態、聚合、編排；聊天 UI 是選配的覆蓋層 |
| 怎麼接 Claude | 三條路並存（§2）：Agent SDK（API 計費）／CLI＋channel／互動 CLI＋讀逐字稿（訂閱計費） | 直接 spawn 各家 CLI（預設帶 `--dangerously-skip-permissions`，「worktree 就是沙盒」）；狀態靠 OSC 9999 與**裝進 agent 設定檔的 hook** |
| 監控的核心問題 | 「哪些 session 在等我？」（attention list） | 「哪些 agent 在做、在等、做完、卡住？」（Needs You／Working／Done／Idle 看板＋事件流） |
| agent 當使用者 | 否（agent 不叫 BAT） | 是：`orca` CLI `--json`、混合式 skill、worktree checkpoint、orchestration 的 worker 合約 |

本 repo 的位置跟 Orca 比較像（PTY＋hook，不內嵌 SDK），但 Orca 在「狀態的種類、衰減、看板」上細很多；BAT 的「需要我」清單是單人多會話最實用的設計，也是我們 F-71／F-73 做到一半的那件事。

## 2. BAT：自己串 Claude 的三條路（`plans/claude-channel-agent-plan.md`、`plans/claude-cli-transcript-agent-plan.md`、`node-sidecar/`）

| 路 | 做法 | 看得到什麼 | 計費 | 狀態 |
|---|---|---|---|---|
| **SDK**（`handlers/claude-send.mjs`、`lib/live-query.mjs`） | Node sidecar 載入 `@anthropic-ai/claude-agent-sdk`；一個 session 開一條 streaming-input `query()`（CLI 子程序活著跨多輪，省 3–4 秒冷啟動）；`canUseTool` 回呼→App 的核准 UI；`AskUserQuestion` 另出卡片 | 全部：文字串流、thinking、tool_use／tool_result、usage、rate-limit、subagent、`interrupt`／`stopTask`／`setModel`／`setPermissionMode` | API 另計 | 主路 |
| **Channel**（`runtimes/claude-channel-*.mjs`） | 跑互動 CLI，用 `--dangerously-load-development-channels` 掛一個 MCP channel server；輸入用 `notifications/claude/channel` 推進去；**輸出改靠 http hooks**（PreToolUse／PostToolUse／MessageDisplay／Stop／SubagentStart…POST 到 loopback bridge） | 文字（逐行）、工具、turn 邊界、subagent；**看不到 thinking 與主模型 token** | 訂閱 | 實驗（`BAT_DEBUG`） |
| **CLI 逐字稿尾巴**（`runtimes/claude-cli-*.mjs`） | PTY 跑互動 `claude --session-id <uuid>`；**內容從 `~/.claude/projects/<slug>/<id>.jsonl` 增量 tail** 分類成 you／message／tool／thinking／usage；hooks 只拿「工具開始」與 Stop 當即時訊號、PreToolUse 阻塞型做核准轉接 | 幾乎全部（含 thinking、usage） | 訂閱 | 零件驗證完（15,909 幀 0 例外） |

值得記的設計原則（都寫在計畫文件裡，不是事後歸納）：

1. **一個訊息合約，三個 runtime 各自轉接**：renderer 只認 `claude:*` 事件（status／stream／message／tool-use／tool-result／result／turn-end／error／permission-request／ask-user／rate-limit／task／modeChange），「UI 永遠不依 transport 分支」。
2. **每個關注點只有一個事實來源**（逐字稿路的 authority split）：畫面與輸入＝PTY；內容分類＝逐字稿；「工具開始」與 turn 邊界＝hooks；核准＝hooks（阻塞型）。
3. **能力探測驅動 UI**：`supportsStreaming`／`supportsPermissionMode`／`supportsStopTask`… 用探測結果停用控制項，「不假設 parity、不崩潰」。
4. **中斷是「這一輪」不是「整場」**；殺整個 CLI 只是後備。
5. **計費路徑要在畫面上看得見**（「Subscription (CLI)」vs「API (SDK)」徽章）；文件引用 2026-06-15 生效的政策：互動式算訂閱、`claude -p`／SDK／Actions 走另計額度。
6. **觀測類 hook 必須立刻回**，只有核准路可以阻塞；核准要有 timeout（預設交回 TUI），卡住的 UI 不能卡住 agent。
7. **harness 雜訊要過濾**（`lib/harness-noise.mjs`）：逐字稿裡 `role: user` 不一定是人打的——`<task-notification>`、`<local-command-caveat>`、`[Request interrupted by user for tool use]`、壓縮摘要（「This session is being continued…」）都會被當成「你說的話」而排擠真正的提示；Rust 端 `normalize_session_hint_text` 鏡射同一套規則。
8. **延遲取樣量對的東西**（`lib/latency-sample.mjs`）：`apiMs`／`ttftMs`，不是 `wallMs`——wall 時間含人核准工具的等待，說不了 API 快慢；每筆樣本自帶 model／effort／window 維度。
9. Remote Control（`claude --remote-control`）看過、**明確不用**：協定不公開、強制 claude.ai OAuth、流量過 Anthropic 雲；第三方只拿得到 hooks＋channels。

### 2a. BAT 的監控資訊

- **Statusline**（15 項可拖拉）：session id（點了 resume）、分支、tokens、turns、時長、context %、成本、5h／7d 用量與重置倒數、最大輸出、快取效率、提示歷史。
- **快取成本意識**：每輪快取讀寫與成本；閒置 1 分鐘後浮出 5 分鐘／1 小時快取 TTL 倒數；**送出前若 >150k 已快取 token 過期（閒置 >1h）跳確認**，避免無意間全價重算。
- **Subagent 追蹤**：進度、耗時、`[stalled]` 停滯標記。
- **「需要我」清單**（`docs/mockups/attention-list.html`、`utils/attention.ts`，已實作）：
  - 側欄小點：黃呼吸＝10 秒內有輸出（在跑）、**亮綠＝做完了你還沒看（新）**、暗綠＝看過了、紅 `?`＝等你核准。
  - 鈴鐺徽章：**紅（有等核准）＞綠（做完沒看）＞灰（在跑的數量）**，沒事就不顯示；切到那個 workspace 就退成已看。
  - 清單每列第二行＝該 session 最後一段 assistant 回覆前 40 字（零成本）；等核准的列直接有「核准」鈕；跨視窗。
  - 「最小版本：只做亮綠 vs 暗綠這一件事」——光看側欄就知道誰做完沒看。
- **Auto-continue**（`/ac N`）：turn 以 success 結束才自動再送，計數在 host、手動輸入就歸零、畫面標 `[auto N/max]`；文件自己警告「午休前關掉，它會很樂意燒額度」。
- Rest／Wake（暫停 session 釋放子程序）、session fork、帳號 hot-swap、Dock 徽章＋音效。

## 3. Orca ADE：agent 是終端裡的程序，App 負責狀態、聚合、編排（`docs/site/content/docs/`、`src/main/agent-hooks/`、`src/shared/agent-status-*.ts`）

### 3a. 狀態怎麼來

- **兩個來源餵同一個 store**：終端輸出裡的 **OSC 9999** 序列（Claude 的 statusline hook 會吐）＋ **Orca 管理的 hooks**（裝進各 agent 的設定檔，Claude 是 `~/.claude/settings.json`；Settings 可整個關掉並「不重啟就恢復」）。
- **hook 端點寫在磁碟**（`{userData}/agent-hooks/endpoint.env`），每次 hook 執行時重新 source——App 重啟換了 port，活著的 agent 會話仍打得到。（我們用檔案路徑當端點，天生沒這問題。）
- **hook 讀 stdin 的合約**（`hook-stdin-contract.ts`）：PATH 被剝也要能讀（`command -p cat`）、第一個 JSON 值到就回（Grok 不關 stdin）、多位元組字元跨 chunk 不能炸、原樣輸出不重新序列化。這類「hook 壞了不能擋 agent」的硬化跟我們 `hooks.rs` 的原則一樣，但細很多。
- **狀態詞彙**：working／waiting（要核准或回答，琥珀 `?`）／done（翠綠）／blocked（失敗、中斷，紅）／idle（灰）／無（不是認得的 agent）。**衰減規則**：30 分鐘沒新證據，working 退成 active；還原自磁碟但沒確認過的列永遠不算新鮮；done 是終點。
- **「失聯不等於死亡」**：`live`／`unverifiable`／`exited`，只有正向證據才停、丟、重試（R33 已記）。

### 3b. 怎麼呈現

- **Agent Dashboard**（看板）：Needs You／Working／Done／Idle 四欄；卡片＝會話名稱＋最後一則訊息＋年齡；Needs You 染琥珀、Done 染綠，「染色＝看這裡」；點卡片聚焦該終端；子 agent／Agent Teams 當可展開的子列。
- **Agents feed**：跨 worktree 的時間流（做完、卡住、**等太久浮成 blocking**、回覆預覽、新 worktree）；在跑的釘在最上面。
- **通知只在 working→idle 那一刻**；鈴鐺未讀數鏡射到 Dock；可「標為未讀」留待回頭。
- **用量與額度**：從本機讀各 CLI 自己的用量狀態、**80% 警示**。Claude 這條特別：`statusLine` 指令每輪會收到 `rate_limits`（5h／7d 的 `used_percentage`、`resets_at`），Orca 掛一支不輸出 stdout 的 statusline 腳本把它轉進 App——**零成本拿到額度**（OAuth usage 端點會 429）。
- **Awake service**：有 agent 在跑就擋系統睡眠（macOS／Linux 各一個 assertion）。
- **Restart chip**：agent 結束後一鍵同目錄重開；Hibernation 只凍「做完、閒置 30 分、可 resume」的。

### 3c. agent 當 Orca 的使用者

- `orca` CLI 每個指令 `--json`、回收據；`terminal wait --for tui-idle` 讓一個 agent 等另一個 agent 做完。
- **Worktree checkpoint**：每個 worktree 一個自由文字「現在在幹嘛」欄位＋卡片狀態（todo／in-progress／in-review／completed），建議 agent 在「做完一段、推翻假設、卡住、從查到修」時更新，**先讀再寫、保留使用者寫的**。
- **Orchestration 的 worker 合約**：`worker_done` **只送一次**、一定帶 `--outcome succeeded|failed` 與「做了什麼／發現什麼／剩什麼」；長工作送 heartbeat；**卡住用 `orca orchestration ask` 問協調者，不要用 TUI 提示**；決策閘（decision gate）擋住任務直到有人決定。
- **Automations**：排程跑 prompt；`--precheck` 便宜探針失敗就記 skipped；`--reuse-session` 接續上次的終端。
- **文字生成走 agent CLI 子程序**（`text-generation/`）：commit 訊息、分支名、會話名稱——等於 Orca 也有自己的「程式化呼叫」，但只用在小而短的生成。
- 混合式 skill（R33 已記）：stub＋版本相符的 `skills get`；App 偵測過時並背景更新。

## 4. 對照本 repo：差在哪

| 面向 | Orca／BAT | 我們現在 | 判斷 |
|---|---|---|---|
| 狀態種類 | working／**waiting(需要你)**／**done(做完)**／blocked／idle，done 會分「沒看過」「看過」 | Stop→`waiting`「這一輪做完了，等你回覆」跟 permission→`blocked` 都算「等你」（紅點、徽章都數） | **做完一輪**跟**要你核准**混在一起；也沒有「看過了」的概念，徽章數字不會因為你看了而退 |
| 等核准時知道是什麼 | BAT：`Bash: rm -rf dist`；Orca：卡片帶待答問題摘要 | `Notification` 的 message（「Claude needs your permission to use Bash」） | 看不到指令本身，得切過去才知道要不要准 |
| 處理中在做什麼 | 工具名＋耗時、subagent 停滯 | 只有「處理中」 | 跑了 20 分鐘的會話，分不出在跑測試還是卡住 |
| 狀態衰減 | 30 分沒證據退成 active；等太久浮成 blocking | 永遠停在最後一個 hook 事件 | 會話被遺忘時狀態會說謊 |
| 額度餘光 | 5h／7d 用量、80% 警示、快取過期提醒 | 無 | 使用者天天在意 4 小時上限（這輪指令就寫了） |
| 程式化呼叫的計費 | BAT：畫面標「API／Subscription」；刻意避開 `-p` | `claude -p` 四處用，沒標示、沒計數（#76） | 要先讓它**看得見**，再決定要不要限制 |
| 逐字稿雜訊 | 兩邊都過濾 task-notification／caveat／中斷標記／壓縮摘要 | `transcript::user_text` 只排 `isMeta` | 從壓縮摘要接續的會話（像本場）第一句會是「This session is being continued…」，`ctx sessions` 的標題與第一句會錯 |
| hook 回應紀律 | 觀測類 hook 立刻回、核准路才阻塞、有 timeout | Stop hook 會讀逐字稿尾巴再回 | 應量一下；原則要寫進 DEVELOPMENT.md |
| 機器睡眠 | 有 agent 在跑就擋睡眠 | 無 | 夜間迭代靠使用者自己不蓋筆電 |
| agent 卡住怎麼問人 | `ask` 給協調者、決策閘 | `report_status blocked`→收件匣卡片；回答要切到會話打字 | 差一個「在卡片上回答」 |
| 內嵌 SDK 聊天面板、channel、auto-continue、orchestration DAG、hibernation、fork、帳號切換 | 有 | 無 | **不抄**（見 §6） |

## 6. 不抄的，理由

- **內嵌 SDK 聊天面板／channel 路**：我們的定位是「其他 agent 工具的脈絡層」（VISION F-31），終端就是介面；內嵌會變成跟 BAT 拼面板，而且 SDK 路走 API 計費，正是使用者不要的。
- **Auto-continue**：違反「打斷要自己掙得」與省額度；夜間迭代由人指定範圍與時限即可。
- **Orchestration（Run／Task／Dispatch／heartbeat）**：多 agent 平行比較（F-28）還沒有真需求；worker 合約裡值得的那一句（「卡住用 ask 問人、做完只回報一次並帶結果」）我們的 handoff／report_status 已有，差的是 F-85 的回答出口。
- **Hibernation／Rest-Wake／fork／帳號 hot-swap／手機**：單人、單帳號、本機。
- **Orca 預設 `--dangerously-skip-permissions`**：我們不替使用者決定信任；`agent.command` 在 config 裡，想加自己加。
