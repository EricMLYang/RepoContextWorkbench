## 1. 看到的模式

1. **心中的標準是 VS Code**（12 項裡 6 項）：灰色忽略檔、git 上色、右鍵複製、IME、分割編輯、刪除。使用者不是在要新功能，
   是在補「VS Code 檔案總管／編輯器本來就有、這裡沒有」的落差。照這個標準還缺的：**在 Finder 中顯示**、**用預設 App 開啟**
   （PDF、docx、圖片以外的二進位現在只能看大小）、刪除後**復原**（VS Code 的 ⌘Z）、拖曳搬移、多選。
2. **一眼看懂現在的狀態**（4 項）：哪個 Agent、context %、額度剩多少與何時重置。共同點是「不用想就能做判斷」——數字要寫成
   能直接決定動作的樣子（剩多少，而不是用了多少）。
3. **「現在跑的是哪一版」看不到**（4 次提問）：每個改動的 commit 都寫「真 App 未實測（要重裝）」，8d-17～8d-20 四項都還沒驗；
   這次檢討時 /Applications 那份是 10-28 22:49 裝的，之後的「剩多少」「移到垃圾桶」兩個 commit 都不在裡面——使用者沒辦法自己看出來。
   **小修改越多，這個缺口越痛**：改了看不到，就只能每次問 agent。
4. **留痕**：10-28 那場會話做了三個 commit 但沒有交接；10-29 那場結束沒交接（hook 補了提醒）。小修改的痕跡只在 commit 裡，
   這可以接受（commit 訊息已寫清楚做了什麼、測了什麼），但沒交接會讓下一場開場的「上次交接」停在更早的事。

5. **同一類問題只修了一處**（11-02 夜裡反覆檢討時看到）：10-19 修的「輸入法選字按 Enter」只修了 Enter 的 keydown——
   表單的隱式送出（會話列回答框、終端搜尋）與「組字中按 Esc」都還會出事；狀態列加了東西之後 1280 寬就切掉右邊。
   **修一個體驗 bug 時，要順手找同一類的其他地方**。
6. **同介面的缺口**：agent 有 `search_knowledge`（知識＋程式碼＋判斷），人在 App 裡只能用檔名找。
