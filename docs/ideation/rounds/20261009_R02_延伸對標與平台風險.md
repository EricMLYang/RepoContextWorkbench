## 2. 對標掃描
- 查詢：跑完 R01 留下的 8 條，再處理待查名單，並對 Orca、Beads、LLM Wiki 用延伸法（共 13 條）。重要的 4 個用 WebFetch 讀了原文（✅）。
- 新增對標 18 個（完整列在 benchmarks.md），三個發現會改變判斷：

**① 跨 repo 脈絡不是空白，但同類都很小（回答 R01 問題 1 的前半）**
- multi-repo-agent（mra）✅ 是目前最接近的同形狀：自動偵測相依（5 種掃描器）、`--with-deps` 一起載入、依相依順序開 PR、MCP 9 個工具、專案知識庫帶 [DECISION] 標記。不過只有 2 顆星，而且偏程式碼相依，沒有人的判斷、交接、收件匣。
- dev.to〈The context problem nobody solved〉✅ 整理了 5 種現有做法，各自的缺點寫得很清楚；它提出「寫入範圍由檔案系統強制」，比本工具的 `cross_scope`（只擋 MCP／CLI）更硬。
- 💭 結論：市場承認這個痛點，但沒有成熟產品。**本工具的差異（人的判斷＋交接＋收件匣＋知識 repo，而不只是程式碼相依）依然成立。** 可以抄 mra 的相依掃描器和依序開 PR。

**② 判斷留痕已有標準格式，但沒有跨 repo（回答 R01 問題 1 的後半）**
- AgDR ✅：`docs/agdr/` 的 md＋YAML，Y 句型、考慮過的選項、agent／model／trigger 中繼資料、proposed→executed→superseded、Claude Code `/decide` skill。49 顆星，限單一 repo，沒有搜尋。
- AI Agentree 🔗：判例搜尋（向量）加結果追蹤，是雲端平台。
- DiffMem、MarkMem 🔗：證明「純檔案＋git」就能做出有時效的事實（valid_until＋successor，歷史交給 git）。
- 💭 結論：F-07 不需要引入圖資料庫，照 MarkMem／AgDR 的 supersedes 欄位做就好，**升為功能第一優先**。另外新增 F-40：可匯出成 AgDR 相容格式，讓 spine 的判斷其他工具也讀得到。

**③ 平台風險：Anthropic 正在做單 agent 的記憶與整理（新問題）**
- Code with Claude 2026（5 月）✅：Managed Agents 記憶（以檔案存放）、**Dreaming**（在會話之間排程整理記憶，抽出重複錯誤與偏好）、**Outcomes**（另一個 agent 用 rubric 評分）、多 agent 協作。
- 🔗 2026-09-17 Claude Code Projects：一個協調 agent 把目標拆給多個雲端 thread，各自開分支，**共享專案記憶**。
- 💭 結論：「單一 agent 跨會話記得事情」「排程反芻記憶」平台會做，而且會做得比我們好。本工具的護城河要放在**平台不碰的地方：多 repo 的關係、人的判斷與裁決、人看得懂的 spine**。對平台採整合不重做：新增 F-44，讓 spine 摘要可以匯出成平台的檔案式記憶。下一輪的最大風險查詢是「Projects 會不會往跨 repo 走」。

其他：
- **Tasks vs Beads（回答 R01 問題 2）**：Tasks 管 session 內的執行，Beads 管工作的捕捉，兩者互補。ctx 的 todo 屬於捕捉層，所以 F-19 不會被 Tasks 取代。可以抄 Beads 的「只浮出沒被擋的工作」；Beads 改用 Dolt 後有穩定性抱怨，所以維持 md。
- GSD、Ralph loop：state 放磁碟、每個任務給全新 context → F-42 任務包。spine 本來就是「state 在磁碟」，可以直接接上。
- LLM Wiki 已有可安裝的 skill → F-06 改成整合不重做。
- 中文推送降噪：比照 Lucene CJKBigram＋StopFilter，加哈工大停用詞表；先不加 jieba-rs（AGENTS.md 要求依賴從嚴）。
- Tauri 發佈：notarytool、首次安裝用 .dmg、updater 讀 GitHub Releases 上的 latest.json。

## 5. 排序與建議動手順序
| 順序 | ID | 項目 | 大小 | 準則 | 理由 |
|---|---|---|---|---|---|
| 1 | N-01 | spine 自動 commit＋remote | 半天 | 留痕 | 連兩輪都是 3 份沒 commit，還在累積 |
| 2 | N-03 | 推送降噪＋已推過就降權 | 半天 | 脈絡 | 同 3 筆雜訊連兩輪出現 |
| 3 | N-14 | hook 拒收沒有 session_id 的輸入／`--dry-run` | 1 小時 | 留痕 | 小改動，能防止 spine 被汙染 |
| 4 | N-02 | search 改有型別的結構＋常駐快取 | 1 天 | 脈絡 | 持平 2–3 秒 |
| 5 | N-04 | CI | 半天 | — | 合併 main 前必要 |
| 6 | F-07＋F-40 | 有時效的判斷（supersedes／valid_until）＋AgDR 相容匯出 | 1～2 天 | 留痕、脈絡 | 外部已驗證做法，是我們差異化的核心 |
| 7 | F-33 | 相依掃描器（抄 mra） | 1 天 | 脈絡 | 也就是未結事項 #11 |

定位調整（💭）：「脈絡層＋判斷留痕」再加一句：**單 agent 記憶交給平台，ctx 做平台不做的跨 repo 與人的判斷，並提供匯出接上平台**。
