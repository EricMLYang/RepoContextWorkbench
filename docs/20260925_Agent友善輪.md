# Agent 友善輪（2026-09-25）

> **性質**：檢討＋落地記錄。前一輪（09-12）以工作台為主角、agent 是被請進來的客人；
> 這一輪把 agent 當主要使用者。**程式已落地、測試全綠**；尚未在使用者本機掛 Claude Code（需使用者跑 `ctx setup --claude`）。

## 2. 落地

**新模組**
- `agentapi.py`：agent 一次工作的節奏——`where_am_i → context_for → next_work → log_decision／add_todo／close_todo → report_status → handoff`，另有 `search_knowledge`。全部回 JSON-able dict；錯誤是 `AgentError(code, message, hint)`。MCP 工作層、CLI、hooks 三個入口都呼叫這裡。
- `knowledge.py`：知識 ↔ repo 相關度。BM25 over 各 repo 的 md（中文字元 bigram＋英數單字），洩密檔不進索引，mtime 快取在 `.state/knowledge_index.json`。回傳檔案＋行號片段＋repo 排名。
- `hooks.py`：Claude Code SessionStart 依 cwd 注入精簡脈絡並記下開場 HEAD；SessionEnd 若沒交接但有 commit／未提交檔／留痕，落一筆 `suggestion [hook]` 到收件匣。未登記目錄完全靜默；任何錯誤都吞掉（hook 不能擋住開 agent）。
- `agentsetup.py`＋`assets/SKILL.md`：`ctx setup --spine <路徑> [--claude] [--dry-run]`——記住 spine；`--claude` 另外做 `claude mcp add --scope user`、把 hooks 合併進 `~/.claude/settings.json`（先備份 `.bak-ctx`，冪等）、安裝 skill。

**範圍從約定變成機制**：沒指定範圍＝依 cwd 推出主場（所在 repo 所屬的組）。查詢預設只回主場；寫入主場以外（`add_todo`／`log_decision`／`close_todo`／`handoff`）回 `cross_scope` 錯誤，使用者同意後帶 `cross_scope_ok=true` 才寫得進去。主場不明（cwd 在 spine 或未登記目錄）時不擋。

**MCP 分層**：預設只開 9 個工作層工具（JSON 回傳、參數都有說明、`report_status` 有 enum）；管理層 24 個工具要 `ctx mcp --admin` 或 config `mcp.admin: true`。叫到沒開的管理工具，錯誤訊息會說要 `--admin`。`open_loops` 補上範圍過濾。

**CLI**：`where／context／next／log／todo add|close／status／handoff／search／hook／instructions／setup`；`--json` 放在子命令前後都認；`loops／query／collect／group／registry list` 也支援 `--json`。exit code：0 成功｜1 紅字／一般失敗｜2 請求被拒｜3 找不到 spine。spine 解析：`--spine` ＞ `REPOENGINE_SPINE` ＞ `ctx setup` 記住的 ＞ cwd。輸出自己設成 UTF-8，不必再先設 `PYTHONUTF8`。

**交接是下一次的起點**：`handoff` 落一筆第一行「交接：…」的 decision（含「下次從這裡接：…」），`remaining` 每項各開一個未結。工作摘要的「可接續的一步」排序改為：逾期未結 ＞ 上次交接的下一步 ＞ 其他到期未結 ＞ 閾值提醒。

**工作台**：會話清單顯示 agent 自己回報的階段（處理中／等你回應／卡住了／已交接），`waiting`／`blocked` 亮紅點。

**順手抓到的舊 bug**：`pack._doc_files` 用 `git ls-files` 沒加 `-z`，git 預設把非 ASCII 路徑跳脫加引號，**中文檔名的 md 全部被默默略過**——打包、文件地圖、碰撞選料都受影響（card_notes 大多是中文檔名）。已修並補回歸測試。
