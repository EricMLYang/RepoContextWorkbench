## 0. 一句話診斷

**現在的畫面是「監控頁下面黏一塊 terminal」，不是工作台。** 三份標準裡的操作單位（repo 組合／任務／會話）在畫面上都不是一級物件；畫面的一級物件仍是「repo 清單」與「事件 log」。「太像玩具」的根因在工作台設計 v1 §1 已經自己點出——**只能看不能做**——但改版後這一點沒有真的解掉：全畫面唯一能對事件做的動作還是「忽略並記錄」。

## 1. 逐項發現（按嚴重度）

### 🔴 F1. 行動出口全是文字，不是按鈕——四判準的「有行動出口」在 UI 層是假的

| 位置 | 畫面上看到的 | 實際 | 程式證據 |
|---|---|---|---|
| 需要你判斷的 | `→ 〔降 tier〕〔本週排進度〕` | 純文字，點不動 | `brief.build_questions` 回傳字串，`renderScan` 直接 `el("div","body warn",t)` |
| 碰撞回程 | `〔照建議落〕〔改落點〕〔升格 incubator〕〔深撞：開 agent 視窗〕〔丟棄並記錄〕` | 純文字，寫在事件 body 最後一行 | `collide.run_judgement` 把五個〔〕串進 body |
| 未讀事件 | 「忽略並記錄」 | **唯一真按鈕** | `renderState` |
| open loops | 「關閉」 | 真按鈕，但沒有「延期」「開碰撞」 | 同上 |

v2 §4 規格明寫「監控台事件列：每則事件帶〔開碰撞〕〔進 inbox〕〔開深看〕〔忽略並記錄〕」；工作台設計 v1 §5 第 5 條也承認「差 UI 接線」。**這條沒接，其他什麼都不用談**——使用者看到問句、看到出口的名字、卻只能去 terminal 手打指令，體感就是「介面只是在跟我報告」。

### 🔴 F2. 三種「等我處理」的東西用三種格式疊在一起，沒有統一的待辦模型

事件流分頁由三段拼成，來源與生命週期各異：

| 段 | 來源 | 重算頻率 | 回答後會怎樣 |
|---|---|---|---|
| 需要你判斷的 | `/api/scan` 閾值問句 | 每 2 分鐘或手動 | **不會消失**（沒有 chosen 落點，明天同一條還在） |
| 未讀事件 | 脊椎 pending | 每 5 秒 | 忽略後消失 |
| 未結 open loops | 脊椎 open-loop | 每 5 秒 | 關閉後消失 |

三段各自一種排版（編號列／日期＋tag＋body＋按鈕／#號＋due＋body＋按鈕）。使用者要處理的其實是同一種東西：**一張帶問句與出口的卡，答了就留痕消失**。現在卡的形狀有三種，答法也不一致，而且最重要的那一段（問句）根本答不了。

### 🔴 F3. 自己丟的想法變成一則「待忽略」的未讀

截圖 `ws_events.png` 第二列：`collision [hotkey] opened 輸入：把 card_notes 的對撞流程搬到 repo 尺度…` 旁邊掛著「忽略並記錄」按鈕。這是 `opened` 事件被 `notify.pending` 當一般事件放進未讀。使用者的心智模型是「我丟了一個問題進去、等回答」，畫面卻把他的提問當成一件要他處理的事。**應該呈現為「處理中」狀態卡（無按鈕、有轉圈或時間戳），回程到了原地換成判定卡。** fire-and-forget 沒有等待介面是對的，但「送出後這件事去哪了」要看得到，否則 toast 消失後就是黑箱。

### 🟠 F4. sidebar 是 registry 管理器，不是「挑牌」

收斂檔 §7：起手式是「這件事關係到哪幾個 repo」。畫面上：

- 「組」是一個 `<select>`；「臨時組合」是 13 個 checkbox 的勾選狀態；tag 篩選是第三套選取機制。三套機制決定同一件事（範圍），彼此沒有視覺關聯，範圍結果只顯示在 topbar 一行灰字 `範圍：全部`。
- 預設全勾＝13 個 repo，等於「沒有挑」。而 v2 §4.5 樣貌 A 是以「組」為單位產簡報的。
- 色點制 tag 沒有字，hover 才知道是哪個 tag；13 列 × 2 色點在 1280 寬全靠記色。
- 每列右側 🏷 與 ▶ 兩顆 11px 灰按鈕，opacity .5，正是 L4 上一輪「▶ 沒 work」的同族問題（改成永遠可見了，但仍然幾乎看不見）。
- 300px 固定寬，repo 名截斷（`ForwardDeployedEngi…`）；狀態微標 `🤖｜dirty 3×5d｜↑2｜↓1｜wt×2｜59d` 用「｜」串在 11px 字裡，密到無法瞄讀。

「組」應該是一級物件（一張牌組卡：名字、成員、狀態摘要、這組進行中的碰撞與會話），臨時組合＝一張未命名的牌組卡。現在它只是 select 裡的一個 option。

### 🟠 F5. terminal 面板與上半部沒有任何關係——會話「無主」

- 空狀態文案「＋agent 會話＝打包目前勾選範圍開 claude」佔畫面下 1/3，什麼都沒有。
- 會話 title 是 `claude:全部`／`claude:MI_PM`；開三個會話就分不出誰在做什麼（`term.create_agent` 的 `scope` 只有 repo/group/臨時/全部四種）。
- 事件卡上沒有「深撞：開 agent 會話帶碰撞上下文」；會話 tab 上沒有「這個會話是為了哪張卡開的」。Orca 的核心操作單位「session＋任務＋結果」在這裡退化成「shell 分頁」。
- terminal 佔 280px 固定高，主欄在 1280×860 下只剩約 430px 給事件流，有事件時三則就要捲。

### 🟠 F6. 早晨簡報——「系統心跳」（收斂檔 §6 儀式 1）——藏在第二分頁，形態是一個按鈕＋一個 `<pre>`

- 簡報內容與事件流「需要你判斷的」是**同一資料源**（`brief.build_questions`），畫面上兩處出現、兩處都答不了。
- 簡報應是「早晨開工時，收件匣被整理成三段的那個樣子」，不是另一個要人去點的分頁。要嘛預設面就是簡報形狀，要嘛簡報是收件匣的一種時間切片視圖。
- `<pre>` 純文字讓 v2 §4.5 樣貌 A 的〔〕出口同樣點不動。

### 🟡 F7. 視覺層級：沒有焦點，色彩語意混用

- 全畫面同一 13px 字、同一灰階；最亮的元素是 topbar 三顆按鈕與「丟進碰撞」，而不是「需要你判斷的」三條。
- 紅色用在三處、三個意思：interrupt 事件（准打斷）、registry audit 紅字（漂移）、未讀 badge（計數）。四判準只有 interrupt 有資格用「打斷色」。
- 「需要你判斷的」用橘色 warn，但 sidebar 的 `st.bad`（dirty≥4 天／落後遠端）也用橘，兩者不是同一級。
- 1280 寬空狀態時，主欄 60% 是空白；1920 寬時 sidebar 仍 300px、主欄拉成 1300px 寬的一行行文字，可讀性反而下降（沒有 max-width）。

### 🟡 F8. 狀態列常駐一排 0 與 n/a

`碰撞 0｜outcome 回連 0｜命中率 n/a｜生出 repo 0｜存活率 n/a` 佔據最顯眼的底部常駐位置。這些是北極星量測（收斂檔 §11），原型期全為零，資訊量為零卻永遠在。真正有用的「採集於 08:11｜範圍：全部」排在後面。量測沒有樣本時應隱藏，或移到深看。

### 🟡 F9. 輪詢整塊重繪，會打斷正在進行的操作

`refreshState` 每 5 秒對 `#unread`／`#loops` 做 `innerHTML=""` 全量重繪；`rescan` 每 2 分鐘重繪整個 repo 清單（含 tag editor）。正在輸入的新 tag、正在 hover 的列、剛按下去的按鈕都會被打斷。上一輪 L4「▶ 隱形」已經是這個機制造成的一次事故；沒有 key-based diff 前，這類「怎麼又跳掉」的體感會持續出現。

### ⚪ F10. 深看表 13 欄

在深看模式可接受（本來就是要主動開的全量表）。唯一建議：`最後 commit` 一欄 60 字截斷在 980px 寬會擠掉右側 note，可改為 hover 顯示。

## 2. 為什麼會做成這樣——流程上的根因

1. **wireframe 是從「監控頁」長出來的**。工作台設計 v1 §2 的版面圖就是「監控台 + 底下加 terminal 面板」；照著做，做出來自然是監控頁加 terminal。版面沒有從「操作單位」推導——沒有人先畫「早上 08:00，3 條問句、1 則碰撞回程、2 個會話在跑，這一屏長什麼樣」。
2. **v2 §4.5 消費時刻樣貌只寫了 md 文字稿**，〔〕是文字符號；實作時字串直通 UI，出口就變成了字。「消費樣貌先行」鐵律 7 有守，但樣貌只到文字層，沒到互動層。
3. **測試守得住功能，守不住體感**。`test_page_and_state` 驗「關鍵區塊都在」，通得過的畫面就是現在這一張。UI 的 L4 只能靠人開起來用；這次的 headless 截圖法可以把「開起來看一眼」壓到 30 秒，值得留成腳本。

## 3. 建議的重新框定：以「牌／收件匣／會話」為三個一級物件

```
┌─────────────────────────────────────────────────────────────────┐
│ 碰撞台輸入框（常駐、置中、最亮）          範圍：〔共通 ▾〕  ⚠1  │
├──────────┬────────────────────────────────┬─────────────────────┤
│ 牌       │ 收件匣（統一卡片）              │ 會話                │
│ ▸共通 ●● │ ⚠ 判定失敗 c8      〔重跑〕〔看log〕│ ● claude · c7 深撞  │
│  3 repo  │ ? MI_PM 59 天無 commit          │   AgentCodingPM     │
│  1 碰撞  │      〔降 tier〕〔本週排〕〔開會話〕│ ○ shell · spine     │
│ ▸MI   ●  │ ◐ c7 碰撞中… 08:13 送出          │                     │
│ ▸VMS     │ ✔ c7 真增量 → AgentCodingPM/inbox│ ＋agent  ＋shell    │
│ ＋臨時組 │   〔照建議落〕〔改落點〕〔升格〕〔深撞〕│                    │
│          │ ⏳ #3 pywinpty  due 09-05 〔延〕〔開〕│                     │
│ 深看／audit│ ─ 其餘 10 repo 無異常 ─        │                     │
├──────────┴────────────────────────────────┴─────────────────────┤
│ xterm（可收合）：目前選中的會話                                    │
└─────────────────────────────────────────────────────────────────┘
```

- **牌**：組是一張卡，卡上有成員數、進行中碰撞數、會話數、異常數；點開才見成員與微標。臨時組合＝「＋臨時組」建一張未命名卡，用完可存名。tag 篩選收進「＋臨時組」的挑選對話框，不再常駐。
- **收件匣**：一種卡片，五種狀態圖示（⚠ 准打斷／? 要判斷／◐ 處理中／✔ 已回／⏳ 到期）。每張卡的出口是**真按鈕**，按了落 `chosen` 並消失；「處理中」卡沒有出口。早晨簡報＝收件匣按「要判斷／到期／沉默摘要」三段折疊的視圖，加一顆「存成今日簡報」落 presented。
- **會話**：每個會話有「主」——由哪張卡、哪次碰撞、哪個 repo 開的，title 用任務摘要；卡上的〔開會話〕〔深撞〕直接生會話並互相連結；會話結束時提示「要不要回寫 outcome 到 cN」。
- **狀態列**：只顯示「採集於／範圍／會話數」；北極星量測進深看，有樣本才顯示。

## 5. 對設計檔的回寫建議

- 工作台設計 v1 §2 版面圖需改版為 §3 的三物件版；§5「未完」第 5 條（事件列行動按鈕）應升為 **P0，並註明它是「玩具感」的真根因**，不是收尾項。
- v2 §4.5 樣貌 A／B 補一層「互動樣貌」：每個〔〕對應哪個原語、按下後脊椎落什麼、卡片變什麼狀態。文字樣貌到互動樣貌，才算「消費樣貌先行」走完。
- VERIFICATION.md 回饋迴路補一條：「UI 功能測試通過 ≠ 體感通過；每輪 UI 改動附截圖自看，再進 L4」。
