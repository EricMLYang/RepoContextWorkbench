## 3. 驗證方式與邊界

**自動測試**：`python3 -m pytest -q` → 159 passed, 1 skipped。

**瀏覽器走查**（Chrome 1280×900、暫存 spine、三個假 repo「產品規劃／產品實作／研究筆記」、兩組、一條 PM 關係、一筆屬於產品開發的到期待辦）：

1. 首屏摘要：目標（有來源與時間）、上次進度（脊椎 decision [agent]）、變化（git log／git status）、可接續的一步（open-loop due）
2. 切到知識研究：摘要四格全部誠實說「沒有依據」，卡片與簡報都不含產品開發的待辦
3. 開會話表單：顯示 agent 會拿到什麼、範圍是約定不是權限、三個有情境的起手
4. 會話回報：假 agent 起來時是「程序執行中 · 尚無回報」（琥珀點）；補上 decision／open-loop 後 5 秒內變「最近留痕 21:09」（綠點），終端列同步顯示留痕內容與來源
5. 記錄結果：草稿自動帶出會話期間兩筆留痕＋兩筆未結＋「下次從哪裡接回」待填
6. 首次使用：空 spine → 輸入資料夾 → 預覽出四個候選（含 spine 自己，可取消勾選）→ 命名「產品開發」→ 登記後自動切組並顯示第一次摘要
7. Console 無錯誤
8. CLI：`group summary g1`／`group goal g1 --text "…"` 拿到跟工作台同一份摘要與目標

**未做且不宣稱**：

- 真 Agent 會話（回報狀態是用假 agent＋手寫事件驗的；真 agent 會不會照角色指令留痕，要 L4 才知道）
- 「接續上次工作」帶出的任務在真模型上的實際效果
- Windows／VDI 原生視窗、螢幕閱讀器、完整 WCAG 稽核（本輪沒有重新量字級與對比）
- 檢討 §9 的五項人工驗收（恢復脈絡半分鐘、減少重講背景、辨識責任、隔日接續、維持信任）——這些要 Eric 拿兩組真資料用過才算
