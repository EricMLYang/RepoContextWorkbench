## 2. 設計：四層，由便宜到貴

```
L0 地圖    開場自動注入（~0 成本）   只注入「有關係的 repo」提供什麼（exports），不是全部
L1 定位    search_knowledge（<3 秒） md 走 BM25（標題加權、鄰居加分），程式碼走 git grep；每筆帶 why 與 ref
L2 讀取    read_from（直接讀）       用名字讀 `<repo>:<export>/子路徑`，回傳附 commit，並記一筆引用
L3 委派    ask_repo（幾十秒、花錢）  在對方 repo 開唯讀 agent，對方的 AGENTS.md／skill 自動生效，只回結論＋引用
```

**原則**
- **用名字，不用路徑**：registry 每個 repo 可宣告 `exports`（名稱 → repo 內路徑，像 repo 的 API）；
  關係可標「這條關係用到哪幾個 export」（`relate A B --kind feeds --export 書摘`）。
  搬家只改 registry 一處，`ctx resolve` 永遠給得出現在的路徑。
- **引用不複製；要複製就記版本**：`read_from`／`ask_repo` 自動記引用（誰、讀了誰的哪個檔、當時 commit）；
  手動複製用 `ctx refs cite` 記。上游之後改了 → drift。
- **越用越準**：引用紀錄算出「常被引用卻沒宣告的目錄」→ 建議宣告成 export，地圖自己長出來。
- **讀放寬、寫照舊**：讀其他 repo 不用先問（只讀、有紀錄）；寫入仍受主場範圍限制。

**引用紀錄放哪**：`<spine>/refs/cites.jsonl`，**不是事件檔**——引用不是要人處理的事，
進事件檔會灌爆未讀與收件匣；但它在 spine repo 裡，跟著排程的批次 commit 走，換機器也在。
同一天同 (引用方, 被引用方, 檔, 方式) 只記一次。

## 3. 落地

**新模組**
- `crossref.py`：`resolve`／`read`／`record_cite`／`drift`／`suggest_exports`／`neighbors`／
  `code_search`（git grep，排除 md 與 lock 檔）／`ask_repo`（唯讀 prompt、JSON 回答解析、引用落帳）／
  `lint_doc_refs`（掃 AGENTS／CLAUDE／GEMINI.md 與 skills 的 SKILL.md）。
- `repocard.py`：repo 狀態卡——①上次看過之後的變化（水位線 `.state/seen/<id>.json`，人看卡才推，
  agent 讀不動）②沒 commit 的檔與放了幾天 ③改動依頂層目錄彙總（numstat）④正在跑的程序
  （ps 指令列含 repo 路徑，或 lsof cwd 在 repo 內的常見 runtime；node_modules 裡的子程序略過）
  與「啟動後改過幾個 tracked 檔」⑤最後交接／沒交接的會話 ⑥失效的跨 repo 路徑 ⑦上游變動 ⑧未 push。

**既有模組的改動**
- `registry.py`：`set_export`／`remove_export`／`exports_of`；`relate(..., exports=)`，
  刪 export 時連關係上的引用一起清；`relations`／`relations_of` 帶出 exports。
- `knowledge.py`：標題＋frontmatter＋檔名另建一份索引（權重 2×）；`boosts`（鄰居 ×1.5、
  鄰居 export 內 ×1.2、30 天內改過 ×1.1）；每筆帶 `why`。快取加版本號，舊快取自動重算。
- `agents.py`：`run_text(..., cwd=, read_only=)`；claude 唯讀模式＝`--allowedTools Read Grep Glob LS`
  ＋`--disallowedTools Edit Write Bash NotebookEdit`。
- `agentapi.py`：`search_knowledge` 依主場算 boosts、加 code 結果與 ref；新增 `resolve_ref`／
  `read_from`／`ask_repo`／`repo_status`；`context_for` 多 `neighbors`、`drift`。
- `hooks.py`：SessionStart 注入「鄰居 repo」段（每個鄰居一行 exports）與上游變動。
- `mcpserver.py`：工作層 +3（`read_from`／`ask_repo`／`repo_status`，共 12）；
  管理層 +2（`registry_export`／`refs_check`）；`registry_relate` 可帶 exports。
- `cli.py`：`resolve`／`read`／`ask`／`repo`／`refs check|drift|suggest|cite`／
  `registry export|unexport|exports`／`registry relate --export`；`registry audit` 併入文件路徑失效；
  `search` 顯示 why 與程式碼命中（`--no-code` 關掉）。
- `assets/SKILL.md`：「跨 repo 參考」一節（四步由便宜到貴＋用名字不用路徑＋讀放寬寫照舊）。

**config**：`provider.ask`（ask_repo 用哪個 provider；沒設＝claude——這個動作本來就要 LLM，
不跟 `provider.default: mock` 走）。

## 4. 驗證

- `python3 -m pytest tests -q -m "not agent"` → **204 passed**。`test_crossref.py` 18 條釘住：
  export 驗證（不存在／跳出 repo／名稱字元）、resolve 各形式與 traversal 拒絕、read 的 commit／
  同日去重／自己讀自己不記／目錄清單／行段／洩密拒讀、drift 只看被引用的檔、suggest 在宣告後消失、

  audit 併入、鄰居加分與 why、標題命中、程式碼搜尋、ask_repo 唯讀旗標與 cwd 與引用落帳、
  狀態卡水位線（agent 不推）／目錄彙總／dirty 天數／正在跑的程序（子程序與別 repo 的不列）、
  開場注入鄰居地圖與 drift、MCP 與 CLI E2E。
