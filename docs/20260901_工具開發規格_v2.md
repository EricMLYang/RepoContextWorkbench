## 0. 骨架鐵律（v2 增至七條）

1. **通用引擎／私有分離**：引擎是足以開源的通用專案；repo 清單、路徑、偏好、儀式組裝全在私有層設定檔。引擎裡不出現「Eric」「PM_Head」任何字樣。
2. **資產是兩份純文字，程式碼是耗材**：registry（空間軸、就地更新）＋脊椎（時間軸、append-only）。引擎與薄殼 build-to-delete；資料層永遠可被下一代工具直接讀。
3. **監控預設面過四條判準**：餘光可見、無事不報、有行動出口、打斷要掙得。全量狀態只存在於深看模式。
4. **本地優先、pull 式**：無伺服器、無 webhook、無雲端帳號；外部資訊在儀式時刻或手動觸發時用 API 拉。
5. **教練規格從第一筆日誌開始**：每個原語出手自動寫脊椎。這是 M1 的第一個實作項。
6. **Agent 無關性**：引擎不綁任何單一 coding agent——agent 既是可插拔執行器（P15/P16 provider），也是引擎使用者（MCP）。**但無關性驗證（第二家 provider）是開源前置作業，受護欄 2 管——儀式滿四週前不做。**
7. **消費樣貌先行**（v2 新增，① 的結構性修正）：每個場合在對應原語開工前，必須先有一頁「被消費那一刻」的樣貌（mockup 或 Wizard-of-Oz 實物）。原語序列證明「組得出來」，消費樣貌證明「值得每天回來」——只有前者不准開工。§4.5 為現有草案。

外部零件不變（v1 §1）：coding agent CLIs、`gh`／GitHub API、Repomix、gitingest、自有 `repo-git-sync`／`inbox-dispatch`。**移除**：OS 排程器不再是儀式引信（改 S6）；OS 通知只當「叫人」用，不當互動介面。

⬅⬅ **殼↔引擎唯一通道（④）**：殼只做兩件事——呼叫引擎 CLI（同步或 spawn detached 進程）＋ **poll 脊椎未讀**來決定 badge 與通知。引擎從不回呼殼、殼進程裡不跑任何分鐘級任務；殼顯示的一切內容都來自脊椎。這條把殼↔引擎 IPC 消掉，也讓「殼死了」只等於「晚一點看到」，不等於「事件丟了」。

### 2.5 Agent 整合規格（v2 修訂）

- 方向一（P15）：`AgentProvider` 介面不變；**v1 支援清單改為只有 Claude Code**。第二家 provider（Codex vs Gemini CLI）移入延後區——它驗證的是介面中立性，服務開源信念而非四個場合，屬開源前置作業，受護欄 2 管（儀式滿四週後）。介面設計仍預留可插拔（openab 實證），只是不提前付驗證成本。

## 3. 資料規格

### 3.1 registry.yaml

同 v1（三分法、relation 起手四詞、個人層超集）。補充：`audit` 稽核規則＝tier 與 git 現況比對（active 但 30 天無 commit、paused 無 resume_when、路徑不存在、資料夾在但 registry 沒有）。

### 3.2 脊椎（v2 修訂：文法收緊＋第七種型別）

**事件標頭嚴格文法**（P10 validator 依此拒寫）：

```
## HH:MM <type> [<source>] key:value ...
```

- `<type>` ∈ 七種；`[<source>]` ＝ 哪個儀式/入口（morning-brief/hotkey/manual/…）；後接零到多個 `key:value`（`group:` `repo:` `ref:` `due:` `#編號`）。標頭一行機器可解析，區塊內文自由文字。
- 事件型別 **v2 起手七種**：`presented`／`chosen`／`decision`／`suggestion`／`collision`／`open-loop`（opened 可帶 `due:YYYY-MM-DD`，P13 的「到期」有欄位可查了；狀態變化記新事件不改舊）／⬅ **`outcome`（新增）**：後來的產出回連當初的事件——`outcome [manual] ref:collision:2026-09-15-a` ＋內文寫「長成了 <文章/repo/決策>」。registry 的 `origin` 只有「repo→碰撞」單向血統，靈感命中率需要「碰撞→一切產出」的反向追溯，`outcome` 補這條線；v1 由人在週復盤手記，夜間反芻自動補鏈是延後項。

範例：

```
spine/events/2026-09-01.md
---
## 07:42 presented [morning-brief] group:agent-tooling
呈現了：上游 3 筆更新、repo-x dirty 5 天、open loops 2 條
## 07:45 chosen [morning-brief] ref:presented:07:42
選了：先處理 open-loop #12；忽略 repo-x（理由：本週不動它）
## 21:10 collision [hotkey] group:臨時(repo-a,card_notes)
輸入：<想法>；判定：真增量；落點：repo-a/01_inbox/
## 21:12 open-loop [hotkey] #13 due:2026-09-15
opened →「驗證 X 是否…」
```

**寫入閘（P10 三件套＋去向）**：validator（不合格拒寫）→ file lock（跨行程，⬅⬅ 範圍含 registry.yaml）→ 批次 commit（按儀式收尾或 N 分鐘，不逐事件；⬅⬅ 單一提交者＝S6 timer／儀式收尾，其他進程不碰 git）。⬅⬅ 拒寫去向：MCP 回錯誤給 agent 重試；hotkey 原文落 dead-letter 並浮出未讀。

### 3.4 config.yaml 閾值 schema（v2 新增——「無事不報」的判定規則就是護城河，不能只寫一句「過濾內建」）

```yaml
thresholds:                    # 預設值＝下表；每條都可調，儀式復盤時修
  dirty_stale_days: 4          # dirty 超過 N 天 → 進未讀（低於＝沉默）
  inactive_days: 21            # tier=active 但 N 天無 commit → 「變化」進未讀
  upstream:
    kinds: [release]           # 上游預設只報正式 release（commit 洪流不進未讀）
    prerelease: false
  openloop_default_due_days: 14  # open-loop 未帶 due 時的預設到期
interrupt:                     # 准打斷白名單（其餘一律進未讀）
  - irreversible-confirm       # 不可逆操作待確認
  - costly-anomaly             # 賠不起的異常
  - system-unsure              # 系統自認沒把握（含 P15 agent 呼叫失敗）
```

預設值是起手式，不是答案——**閾值的手感只能用出來**（檢討 ② 的原則），每次覺得「這則不該吵我／這件事怎麼沒告訴我」都是一次免費的校準資料，週復盤時修 config。

### 3.5 環境前提（v2 新增，工程檢討 ③；⬅⬅ ④ 增補後三條）

- **repo 群（含 spine repo）不得住雲端同步資料夾**（Google Drive/OneDrive 串流目錄）：`.git` 內部檔與同步器競爭是已知損毀源，且 P3 高頻 polling＋脊椎高頻 append 在網路檔案系統上又慢又險。現住 Drive 的 repo 先搬本地。
- 跨機（Windows 工作機 ↔ macOS 個人機）同步走 **git remote（GitHub private）**，不走檔案同步。⬅⬅ **先過公司政策確認**（從公司機推個人 GitHub private 是政策題不是技術題）；不通過則退階：個人機單向 pull、或公司內部 git 服務。
- ⬅⬅ **工作機是 Windows 11 Enterprise multi-session（VDI 型環境）**，常駐殼的每個假設都要實地驗：session 登出/回收＝殼死（timer、detached 判定進程的存活策略要對此設計）；toast 權限與 focus assist 可能被 group policy 管；全域 keyboard hook 可能觸發公司 EDR；autostart 能不能設。**M1 前置 Day 0：半天環境 smoke test**（tray 常駐存活／hotkey 攔得到／toast 出得來／autostart 可設），任一失敗當場改方案——比寫完殼才發現便宜。
- ⬅⬅ tray 圖示預設被 Windows 收進 overflow 隱藏區，「餘光可見」的前提要手動 pin 才成立——列入殼的安裝步驟（README 一行＋首次啟動提示）。

### 4.5 消費時刻樣貌（v2 新增，鐵律 7 的現有存貨）

> 兩份都是**草案**：樣貌 A 由 M1 Day 1–3 的 Wizard-of-Oz 實測修訂定稿；樣貌 B 由 M2 前三次真實碰撞修訂。寫作供料與週復盤的樣貌，在各自開工前補（寫作供料的消費時刻＝P16 開窗當下的備料清單，形態較簡單）。

**樣貌 A：早晨簡報（md，一屏內讀完，三段固定結構）**

```markdown
# 早晨簡報 2026-09-01（agent-tooling 組）

## 需要你判斷的（≤3 條，每條一個問句）
1. repo-x dirty 已 5 天，本週要動它嗎？ → 〔開 agent 收尾〕〔標記本週不動〕
2. 上游 repomix v0.9 釋出，含 MCP 介面變更 → 〔看 digest〕〔忽略並記錄〕

## 未結（open loops，只列到期與新增）
- #12「驗證 X」今天到期 → 〔開碰撞〕〔延期〕

## 沉默摘要（一行）
其餘 13 個 repo 無異常、無變化。
```

規則：第一段是「可以直接下判斷的形狀」的定義——**每條都是問句＋出口**，不是狀態陳述；超過 3 條就是過濾閾值錯了。讀完後的選擇記 `chosen`。

**樣貌 B：碰撞回程（送出後分鐘級，通知 → 監控台事件列）**

```
[通知] 碰撞完成：真增量 → 建議落 repo-a/01_inbox/（點擊看詳情）
─── 點擊開監控台事件列 ───
判定：真增量
理由：組內只有 card_notes #87 談過鄰近概念，角度不同
證據：card_notes/030_.../87.md「…」；repo-a/notes/plan.md 無相關段
落點建議：repo-a/01_inbox/
〔照建議落〕〔改落點〕〔升格 incubator〕〔深撞：開 agent 視窗〕〔丟棄並記錄〕
```

規則：hotkey 輸入框**送出即關**（一閃「已丟進碰撞」），人回去做原本的事；判定回來走未讀通知，不打斷（除非 system-unsure）。空窗期沒有等待介面——fire-and-forget 是設計，不是缺陷。⬅⬅ 送出瞬間想法原文已落脊椎（P7 兩段式），判定跑在 detached 進程——殼關掉、session 被回收，碰撞不丟，回程只是晚點到。

## 7. 技術選型（v2 定案）

- **引擎**：**Python 定案**（現有腳本資產＋個人熟練度）。CLI 先行，MCP server 同組原語。
- **薄殼 M2**：⬅ **Windows 單平台、Python 拼裝**（tray＝pystray 類、全域 hotkey＝輕量 lib、通知＝win11toast 類、S6 timer＝殼行程內）——與引擎同語言、夠醜夠快、真的扔得起。**Tauri 不是耗材殼的便宜選項**（整套 Rust 工具鏈投資），與 macOS 一起延後到四週後再評。
- **Agent 整合**：headless＝`claude -p --output-format json`；認證沿用 CLI 登入、引擎零金鑰；不內嵌 terminal；ACP 為後續候選。⬅⬅ 每次呼叫 raw request/response 落檔留底（gitignore）。
- ⬅⬅ **Windows 執行細節（④）**：所有 Python 進程（引擎 CLI、MCP server、殼）一律 `PYTHONUTF8=1`——脊椎全中文，cp950 預設編碼在 console/subprocess 情境會炸；detached 進程 spawn 用 `DETACHED_PROCESS`/`CREATE_NEW_PROCESS_GROUP` 旗標，不掛在殼的進程樹下。
- **授權**：引擎 MIT／Apache-2.0（待選）；不引入 AGPL 程式碼。
