## 0. 一句話診斷

原型的三個一級物件（牌／收件匣／會話）已把「組」做成畫面上的卡，但**引擎裡的組仍只是 id 清單**：
會話開場只給文件地圖（agent 不知道這組是誰、誰管誰、最近動了什麼）；採集只看 dirty／末次 commit（看不到活動節奏與內容）；
registry 的 `relations` 詞彙自 v1 §3.1 就寫在草案裡，**從未有讀寫實作**。三個希望其實是同一件事的三面：**讓「組」在資料層長出語意**。

## 1. 裁定

| # | 裁定 | 理由 |
|---|---|---|
| 1 | **關係存在 registry，不另開檔**：來源 repo 的 `relations: [{to, kind, note?}]` | 兩份純文字資產的鐵律；PM_Head `registry.yaml` 日後可成子集（v1 §3.1 既定方向） |
| 2 | **詞彙表是起手式、config 可擴充**：內建 `pm-of`／`feeds`／`derived-from`／`upstream-of`／`sibling-topic`，每種帶 forward／inverse 兩向讀法；私有層 `relations.kinds` 加自己的 | 不預先設計本體論（收斂檔立場）；「A 是 B 的 PM」直接對應 `pm-of` |
| 3 | **關係的三個入口同源**：CLI `registry relate`、MCP `registry_relate`、工作台深看「關係」段（表單＋✕）；YAML 手改也行 | 「友善」＝在既有畫面裡兩個下拉一個按鈕；agent 也能替你設（人的介面＝agent 的介面） |
| 4 | **監控焦點改為活動脈動**：每 repo `commits_7d`／`commits_30d`／`recent_commits`（最新 5 則主旨）；組級 `group_pulse`；一條跨 repo 的近期 commit 時間線 | 使用者原話；dirty／末次 commit 只回答「有沒有壞掉」，回答不了「這組在忙什麼」 |
| 5 | **脈動是資訊不是問句**：簡報加「脈動（一行）」段、牌組卡 ⟳7d 徽章、深看「近期 commit」表；不新增問句卡 | 無事不報仍守；活動是餘光可見的資訊，不是要人判斷的事 |
| 6 | **預設 agent＝組管家（group steward）**：會話料改為「組情境卡＋文件地圖」；情境卡＝成員與角色（含關係兩向讀法）＋脈動＋本組未結＋本組最近事件＋角色說明 | 融入的意思是「開口前就知道這組是誰、誰管誰、在忙什麼」；角色說明是通用措辭（引擎零私有字樣），config `session.role_prompt` 可覆寫 |
| 7 | **沒給任務時預設任務**＝「先讀情境卡，用 3 行告訴我這組現況，再問我要做什麼」；開會話落 `presented [session] group:<g>` | 讓 agent 主動而不是等指令；教練規格出手留痕 |
| 8 | **audit 補反向 tier 漂移**：dormant 但 7 天內有 commit 也紅字 | 真資料實錘（§4）：活動才是真相，tier 只是宣稱 |

## 2. 資料規格增補

### 2.1 registry.yaml（v1 §3.1 草案落地）

```yaml
repos:
  - id: MI_PM
    ...
    relations:
      - {to: MiCrawler, kind: pm-of, note: MI 線 PM 規劃爬蟲 code repo}
      - {to: MIAgentTest, kind: pm-of}
```

| kind | forward（從來源讀） | inverse（從目標讀） | 用途 |
|---|---|---|---|
| `pm-of` | A 規劃（PM）→ B | B 的 PM 是 A | PM repo ↔ code repo |
| `feeds` | A 供料給→ B | B 吃料自 A | 知識／規範流向 |
| `derived-from` | A 衍生自→ B | B 衍生出 A | 血統（與 `origin` 互補：origin 是碰撞血統，這是 repo 血統） |
| `upstream-of` | A 是其上游→ B | B 上游是 A | 上下游 |
| `sibling-topic` | 同主題（對稱） | 同主題 | 主題相關 |

config 擴充：`relations: {kinds: {tests: {forward: 驗證, inverse: 被驗證於}}}`。
稽核：`[關係斷鏈] A → ghost (pm-of)：目標未登記`；`remove_repo` 連帶清關係。

### 2.2 採集欄位（P3）

`commits_7d`／`commits_30d`（`git rev-list --count --since`）、`recent_commits[{date, hash, subject}]`（`git log -5`）。
`group_pulse(states)` → `{repos, commits_7d, commits_30d, per_repo_7d, active_7d, quiet_30d, most_active, latest}`；
`recent_across(states, limit)` → 跨 repo 時間線；`pulse_line(pulse)` → 一行文字（簡報／CLI／情境卡同源）。

### 2.3 組情境卡（P16 會話料 v2）

```
# 組情境卡 MI（2026-09-08 16:42）
## 成員與角色
- **MI_PM**（active｜MI/pm）：規劃（PM）→ MiCrawler；規劃（PM）→ MIAgentTest
  近 7 天 0 commits｜最新 2026-07-05「chore: …」
- **MiCrawler**（dormant｜MI/code）：PM 是 MI_PM
  近 7 天 4 commits｜最新 2026-09-08「口說稿音轉文結果!」
## 脈動
近 7 天 5 commits／30 天 12（MiCrawler 4、MIAgentTest 1）；最新：…；30 天沉默：MI_PM
## 未結（open loops，本組）
## 最近事件（本組，最多 8 則）
## 你的角色
你是這組 repo 的**組管家**……（先讀卡再動手／以組為範圍彙整並標出處／尊重 PM↔code 關係、不越組／出手留痕／無事不報）
```

情境卡與文件地圖寫進同一個 `groups/<g>/materials/session-*.md`；prompt 改為「先讀情境卡，需要細節再照地圖挑檔」。

## 4. 真資料實測（2026-09-08，真 spine 13 repo）

- 設了 6 條關係（MI／SmartSignage／Aeco 三線的 PM→code 各 `pm-of`；AgentCodingPM `feeds` ForwardDeployedEngineer）——CLI 一行一條，
  `registry relations MiCrawler` 回「MiCrawler 的 PM 是 MI_PM」。
- `pulse --group MI` 立刻看出一個 tier 說不出來的事實：**MI_PM 掛 active 但沉默 66 天，MiCrawler 掛 dormant 卻 7 天 4 commits**。
  舊 audit 只抓前者；本輪加反向漂移紅字抓後者（裁定 8）。這正是「監控看活動不看宣稱」的價值證明。
- `group context MI` 一屏內讀完；打開〔組會話〕後 agent 的開場應是這組的 3 行現況（L4 待人驗）。
